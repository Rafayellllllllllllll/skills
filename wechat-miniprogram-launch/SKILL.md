# 微信小程序上架流程（可复用模板）

## 0. 先问清楚（最多 3 个，给选项）
- 主体：个人（只能开发和发布，不能接支付、不能认证、很多高级接口不能用）还是个体户/企业（能收费）？要收费就必须是个体户或企业主体。
- 类目：优先选「工具」这类好过审的；在线教育、医疗、金融、社交等类目要额外资质，能避就避。
- 是否收费、是否带 AI 功能（AI 生成内容可能要做深度合成或算法备案，第一版尽量只做识别、整理这类功能，并用国内模型）。

## 1. 注册小程序拿 AppID（个人主体约 10 分钟）
1. 邮箱：必须没注册过公众号、小程序、开放平台，也没绑过个人微信；一个邮箱只能注册一个小程序。用用户自己的邮箱，因为它就是以后的登录账号。
2. 打开 https://mp.weixin.qq.com/wxopen/waregister?action=step1 ，填邮箱，密码用 Vault 生成并保存（kind login）。点「激活邮箱」后会有滑块验证码，然后用 Secure Form 让用户填邮箱里的 6 位码，勾选协议后点注册。
3. 信息登记页：类别选「其他」（选了以后不能再改成游戏），国家选中国大陆，主体类型按第 0 步选。
4. 个人主体要填身份证姓名和手机号（先查 Vault 里存的联系人），身份证号用 Secure Form 让用户填。点「获取验证码」后，用 Secure Form 或在聊天里拿短信码。
5. 管理员身份验证要用户用自己的微信扫码，用 request_box_help 把屏幕交给她，扫完点「继续」再确认。
6. 进后台后，在「开发管理 > 开发设置」能看到 AppID（wx 开头）。不要生成或显示 AppSecret。把 AppID 和原始 ID 记进 journal。
7. 名称和类目先别填，等用户定了再填，名称审核通过后很难改。

## 2. 写代码
- 用原生小程序框架（WXML/WXSS/JS），在 project.config.json 里填 AppID，tabBar 跟原产品对齐。
- 后端用微信云开发（cloudfunctionRoot）。数据读写统一放在 services/ 层，先用本地存储和假数据跑通，后面接云开发只改这一处。
- 交给 Cursor 云端编程助手在原仓库新建一个文件夹来写，开 PR，不自动合并，合并要用户明确同意。
- 写完让用户用微信开发者工具导入项目，扫码真机预览。

## 3. 上线前（收费产品要按这个顺序）
1. 办主体：个体户或企业执照（审核要几天到几周）。
2. 主体：个人号不能直接改成个体户或企业主体，一般要新注册一个，或者走官方的主体变更流程，以后台当时的说明为准。
3. 微信认证：个体户或企业主体要交年费，每年认证一次。
4. 小程序备案：在后台「备案」里提交，管局审核最长约 20 个工作日，要尽早做。
5. 支付：会员、解锁这类虚拟商品要走小程序虚拟支付，平台会抽成，具体比例以后台为准；实物商品走微信支付商户号。
6. 拉新：不要用邀请返现金，容易被判成诱导分享。奖励用会员时长、使用次数这类权益。
7. 隐私：在后台填用户隐私保护指引，用到相机、相册、昵称等都要声明。

## 4. 提审发布
1. 在开发者工具点「上传」，填版本号和备注。
2. 后台「版本管理」里把开发版设为体验版，用户自测一遍。
3. 「提交审核」：填功能页面、测试账号、类目对应的资质；有付费功能要写清楚。
4. 审核通过后点「发布」。被驳回就照驳回理由改，再重新提审。

## 注意
- 按用户的设备和偏好调整，不推荐用户用不到的平台。
- 收费、AI 备案、类目这些政策会变，每次以后台和官方文档当时的说明为准，拿不准就查官方，不要瞎说。
